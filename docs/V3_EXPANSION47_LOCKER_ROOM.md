# Expansion 47 — Locker Room and Player Roles

LOCKER ROOM adds a dedicated player-management page using the existing franchise morale engine. Profiles show morale, role satisfaction, trade pressure, expected role, usage context and planned rotation minutes. Before any season appearances, usage is explicitly labeled as the planned rotation; later it reflects the engine's season/recent-game blend. Contextual player perspective text is labeled simulated dialogue, not an actual athlete quotation.

Three meeting responses use existing consequences: Reassure and listen supplies temporary support with a three-game cooldown; Ask for patience supplies temporary patience with a three-game cooldown; Reset expectations honestly withdraws the role promise, returns to automatic expectations, applies the engine's immediate morale cost and sets a two-game cooldown. These are game-based counters, not wall-clock timers.

Seven role presets expose existing minute expectations, with review after three, five or ten team games. An active promise cannot be overwritten to restart its review. It must reach a verdict or be withdrawn through an honest reset meeting. Review follows the existing engine: at least 60% of reviewed games, with a minimum of two, must meet the agreement. Minutes allow a three-minute tolerance, and starter agreements also require a start. Kept/broken outcomes and their morale memory are handled by the production game hook. Promises change expectations; actual rotation entries and player ratings are untouched.

Every response has an isolated preview showing the affected player's before/after morale, team chemistry, resulting expectations and meeting cooldown. Changes to selections invalidate the preview. Confirmation saves to the V3 working checkpoint using its hash guard, temporary candidate persistence, reload verification, a verified recovery copy and atomic replacement. GET and preview are read-only; actions open in the regular season. API version is 0.24.0 with GET/POST /v3/locker-room.

The existing morale subsystem remains authoritative; no parallel satisfaction model, personality score or relationship engine is added. Read snapshots deep-copy the simulation state because the legacy snapshot initializer can migrate morale in place. For the first explicit action, missing persistent player scores are initialized from current context, avoiding the legacy meeting function's arbitrary neutral fallback. That normalization and the response modify only the morale payload.

Player memory shows the latest twenty recorded events for that player and team, including meetings, role agreements, honest resets and promise-review verdicts. Inbox and Pulse role concerns now route to Locker Room. Agreements link to Game Day for rotation management. Existing CPU morale behavior retains the same underlying meeting and promise rules.

Validation covers read-only deterministic snapshots, all meeting responses, cooldown rejection, active-promise protection, kept/broken and idempotent reviews, the actual production simulation hook on a copied state, phase/roster/input rejection, stale/replayed confirmations, temporary checkpoint persistence and recovery, and full state equality outside the morale payload. Preferences, trade state, ratings and rotations remain unchanged. Godot checks cover roster choices, preview invalidation, cooldown controls and navigation. The established morale consequence, Decision Inbox and Expansion 45 regressions pass. Native desktop fixture checks verified profiles, contextual dialogue, agreement options and preview cards. The live franchise was used only for reads and preview, with no conversation or promise committed.
